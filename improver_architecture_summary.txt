METRIC DEFINITION PATTERN:
─────────────────────────

metrics/{metric_name}/
├── config.json           ← Metric configuration
├── examples.lean         ← Tagged theorem examples
├── examples.json         ← Extracted examples (auto-generated)
└── {metric_name}.lean    ← Lean scoring function

CONFIG.JSON STRUCTURE:
──────────────────────
{
  "name": "metric_name",
  "scoring": {
    "score_fn": "metrics/metric/metric.lean",
    "minmax": "min|max",
    "sorry_ok": false,
    "correctness_condition": "eq|compiles|none"
  },
  "prompts": {
    "system_prompt": "...",
    "annotation_prompt": "...",
    "rag_prompt": "..."
  },
  "examples": { ... },
  "llm": { "llm_metric": false, "rubric": null }
}

METRIC ROUTING:
───────────────
metrics/router.lean contains:
  def route_metric(name: String, cs: CompilationStep): IO Float :=
    match name with
    | "length" => length_score cs
    | "readability" => readability_score cs
    | ... => error

BUILT-IN METRICS:
─────────────────
Length         → Minimize tactic count
Readability    → LLM evaluation with rubric (6 criteria, 9 points)
Declarativity  → Maximize "have" statements
Dependency     → Minimize external dependencies
Completion     → Full proof generation (no sorries)
Conjecturer    → Theorem variation proposals

└─────────────────────────────────────────────────────────────────────────────┘

INPUT: Lean Repository Code
   ↓
DATASET: Define files to optimize
   ├─ Repository: Files to process
   └─ Optional: Specific theorems
   ↓
EXTRACTION: Lean metaprogramming
   ├─ Compile each file
   ├─ Identify human theorems
   ├─ Extract structure + metadata
   └─ Generate goal states
   ↓
PROMPT GENERATION:
   ├─ System prompt (metric-specific)
   ├─ Theorem statement
   ├─ Original proof
   ├─ Goal states (annotated)
   ├─ Context (definitions, imports)
   └─ Examples (similar optimizations)
   ↓
RAG ENHANCEMENT (optional):
   ├─ Informal proof retrieval
   ├─ Vector similarity search
   └─ Top-k injection into prompt
   ↓
INFERENCE:
   ├─ Ray dataset creation
   ├─ Batch processing
   ├─ vLLM generation
   ├─ Sampling (temperature, top_p)
   └─ Output: Generated proofs
   ↓
EVALUATION:
   ├─ Lean compilation
   ├─ Correctness checking
   ├─ Metric scoring
   ├─ Delta calculation (improvement)
   └─ Result aggregation
   ↓
ANALYSIS:
   ├─ Accuracy statistics
   ├─ Improvement metrics
   ├─ Best-of-N selection
   └─ Summary reports
   ↓
OUTPUT: Optimized proofs + metrics


┌─────────────────────────────────────────────────────────────────────────────┐
│                    IMPORTANT CONFIGURATION PARAMETERS                       │
└─────────────────────────────────────────────────────────────────────────────┘

INFERENCE PARAMETERS (Ray/vLLM):
────────────────────────────────
temperature: 0.3            # Sampling randomness
top_p: 0.9                  # Nucleus sampling
repetition_penalty: 1.05    # Prevent repetition
max_tokens: 2048            # Generation limit
max_model_len: 16384        # Context window
max_num_batched_tokens: 65536  # Batch token limit
tensor_parallel_size: 1     # Model parallelism
enable_chunked_prefill: true
batch_size: 32
max_concurrent_batches: 32

LEAN EVALUATION:
────────────────
sorry_ok: false             # Allow sorries in proof
correctness_condition:      # Comparison method
  - "eq": output == original
  - "compiles": proof compiles
  - "none": no check

CONCURRENCY:
─────────────
Ray workers: 1 per GPU      # Process parallelism
vLLM concurrency: GPU count # Inference workers
asyncio semaphores: variable # CPU task limiting


┌─────────────────────────────────────────────────────────────────────────────┐
│                      TYPICAL WORKFLOW EXAMPLE                               │
└─────────────────────────────────────────────────────────────────────────────┘

1. DEFINE DATASET
   └─ data/my_dataset.json

2. GENERATE PROMPTS (Lake + Lean)
   └─ ./improver prompts get --dataset_path data/my_dataset.json

3. BUILD RAG (optional, LLM-intensive)
   └─ ./improver rag build --dataset_path data/my_dataset.json

4. RUN INFERENCE (GPU-intensive)
   └─ python ImProver/basic/improver.py "metric" data/my_dataset.json prompts_id

5. EVALUATE (CPU-intensive, Lean compilation)
   └─ python ImProver/basic/eval_improver.py run_id

6. ANALYZE RESULTS
   └─ python ImProver/basic/analysis.py --run_id run_id

OUTPUT:
  evals/{run_id}/
  ├─ data/          (inference outputs, Parquet)
  ├─ evals/         (per-file evaluation results, JSON)
  ├─ analysis/      (aggregated metrics)
  └─ *.duckdb       (queryable tables)

TYPICAL METRICS REPORTED:
  • Accuracy: % of valid generated proofs
  • Improvement Rate: % achieving metric improvement
  • Average Improvement: mean metric delta
  • Best-of-N: best achievable improvement with N samples
  • Compilation Success Rate: % of valid Lean code
